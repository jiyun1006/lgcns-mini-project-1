## 한 줄 요약

**로그인·회원가입 화면과 로그인 서버 준비물(NextAuth, 강사님 API 호출 도구, 로그인 상태 확인)은 `part/auth`에 들어갔다. 하지만 화면은 아직 가짜 API(`mockAuthApi`)에 연결돼 있어서 실제 로그인·가입은 되지 않고, `getCurrentUser()`도 여전히 "DB의 첫 번째 사용자"를 돌려준다. 마이페이지는 프로필·사진·자기소개·공개 설정이 DB에 저장된다.**

## 2. DB와는 어떻게 붙어 있나

**회원 정보는 두 곳에 나뉘어 있다.**

| 저장소                    | 들어 있는 것                                                         | 우리가 만지는 방법                  |
| ------------------------- | -------------------------------------------------------------------- | ----------------------------------- |
| 강사님 Spring 서버 DB     | 이메일, **비밀번호(해시)**, 이름, 숫자 `userId`                      | API로만 (로그인·가입·비밀번호 찾기) |
| 우리 MongoDB Atlas `User` | 이메일, 닉네임(`name`), `loginId`, 관심사, 사진, 자기소개, 공개 설정 | Prisma로 직접                       |

- 채팅·게시판·마이페이지는 **우리 MongoDB의 `User` 번호(ObjectId)**로 "누가 썼나"를 기록한다. 강사님 서버의 숫자 `userId`는 로그인 안에서만 쓴다. (팀 합의: `user.id` = Mongo ObjectId)
- "지금 로그인한 사람"은 공용 함수 `lib/current-user.ts`의 `getCurrentUser()`가 정한다. **`part/auth`에서는 아직 DB 첫 번째 사용자를 돌려준다.** 그래서 비로그인으로도 채팅·마이페이지가 "첫 사용자"로 동작한다. 마이페이지에서 저장하면 그 첫 사용자의 데이터가 바뀌니 테스트할 때 주의한다.
- `getCurrentUser()`를 쓰는 곳은 9군데(채팅 API 5, 마이페이지 4)다. 세션 기반으로 바꾸면 로그인 안 했을 때 `null`이 되므로, 쓰는 곳 전부에 `null` 처리를 **한 PR로** 같이 넣는다.
- 게시판은 `getCurrentUser()` 대신 `lib/board/server-user.ts`의 `BOARD_DEMO_USER_ID`를 쓴다. 로그인을 붙일 때 같이 바꾼다.
- 프로젝트에 Cache Components가 켜져 있어서, 쿠키·세션을 읽는 곳은 `<Suspense>` 안에 두고 요청마다 새로 조회한다.

## 3. API는 어떻게 보내고 있나

**브라우저가 강사님 서버에 직접 가지 않는다.** 화면 → 우리 Next 서버(NextAuth, 서버 액션) → 강사님 서버 순서로 간다.

- 강사님 API 주소는 `.env`의 `NEXT_PUBLIC_API_URL`, 경로는 `config/apiuri.ts`에 모은다.
- 호출은 `lib/fetchClients.ts`의 `springFetch`로 한다. 응답은 항상 `{ success, message, data }` 모양이다.
- 화면은 `service/auth/authApi.ts`라는 **한 곳**만 부른다. 지금은 가짜(`mockAuthApi`)가 꽂혀 있고, 진짜(`realAuthApi`)로 바꿀 때 이 파일의 마지막 한 줄만 바뀐다.

사용하는 강사님 API (테스트 서버 Swagger에서 확인):

| 기능             | 요청                                                     | 쓰는 곳                     |
| ---------------- | -------------------------------------------------------- | --------------------------- |
| 로그인           | `POST /api/v1/auth/login` `{ email, password }`          | NextAuth `authorize`        |
| 회원가입         | `POST /api/v1/auth/register` `{ email, name, password }` | 회원가입 서버 액션 (예정)   |
| 이메일 중복 확인 | `POST /api/v1/auth/check-email` `{ email }`              | 회원가입 2단계 (예정)       |
| 비밀번호 찾기    | `POST /api/v1/auth/password/forgot` → `password/reset`   | 비밀번호 찾기 페이지 (예정) |
| 로그아웃         | `POST /api/v1/auth/logout` (Bearer 토큰)                 | 나중에                      |

- Swagger 확인 결과: 가입 200 / 같은 이메일로 다시 가입 409 `CONFLICT` / 로그인 200 / 틀린 비밀번호 401 `UNAUTHORIZED`
- 비밀번호는 강사님 서버만 보관한다. 우리 MongoDB·쿠키·localStorage 어디에도 두지 않는다.

필요한 환경변수 (`.env`, git에 올리지 않는다):

| 이름                  | 쓰는 곳                                                                                                      |
| --------------------- | ------------------------------------------------------------------------------------------------------------ |
| `NEXT_PUBLIC_API_URL` | 강사님 서버 주소                                                                                             |
| `NEXTAUTH_SECRET`     | 로그인 팔찌(JWT) 서명. **`AuthShell`이 루트 layout에 있어서 모든 페이지가 이 값을 쓴다. 없으면 에러가 난다** |
| `NEXTAUTH_URL`        | 우리 앱 주소 (로컬은 `http://localhost:3000`)                                                                |

## 4. 로그인과 백엔드는 어떻게 연결되나

**`part/auth`에는 연결 고리가 준비돼 있고, 실제로 잇는 코드는 7번 브랜치에 있다.**

1. 로그인 화면 → `signIn("credentials")` → NextAuth `authorize`가 강사님 서버에 로그인
2. 성공하면 **같은 이메일의 MongoDB `User`를 찾고, 없으면 만든다** (`upsert`). 새 사용자에게는 이메일 앞부분으로 `loginId`를 자동으로 붙인다
3. 그 사용자의 ObjectId를 로그인 팔찌(JWT, 2시간)에 적어 쿠키로 둔다. 강사님 서버 토큰은 팔찌 안쪽에만 두고 브라우저 JS에는 주지 않는다
4. `getCurrentUser()`가 "첫 번째 사용자" 대신 팔찌의 번호로 사용자를 찾게 바꾼다 (아직 안 함)

⚠️ **마이페이지 이메일 수정 문제**: 이메일은 강사님 서버와 우리 MongoDB를 잇는 열쇠다. 강사님 API에는 이메일을 바꾸는 기능이 없어서, 마이페이지에서 MongoDB 이메일만 바꾸면 다음 로그인 때 사용자가 **새로 만들어져 데이터가 갈라진다.** → 7번에서 가입 이메일은 읽기 전용으로 바꾸고, 바꿀 수 있는 "복구용 이메일"을 따로 두었다.

## 6. 화면 구성 (간단히)

- 로그인·회원가입 컴포넌트는 `components/atoms`(Button, Alert) → `components/molecules`(TextField, PasswordField, TagInput 등) → `components/organisms`(LoginForm, SignupForm, 회원가입 단계 화면) 순서로 나눴다. 디자인은 팀 목업 기준이고, 색·글자 크기는 아직 하드코딩이다(디자인 확정 뒤 한 번에 바꾼다)
- 마이페이지는 위에서부터 **프로필·기본 정보 → 자기소개·관심사 → 공개 설정 → 비밀번호 변경 → 로그인 관리(로그아웃) → 내 활동 → 회원탈퇴**, 컴포넌트는 `components/mypage/` 아래 atoms → molecules → organisms → templates
- 포인트 색상은 게시판과 같은 버건디(`#A50034`)

## 참고: 겪었던 문제

- **DB 접속 실패(DNS 에러)**: `.env`의 클러스터 주소 오타가 원인이었다. 이런 에러가 나면 먼저 주소 철자부터 확인한다.
- **브랜치를 바꾼 뒤 빌드 실패(`tw-animate-css`를 못 찾음)**: 예전 브랜치에서 남은 빌드 캐시가 원인이었다. 브랜치를 바꾼 뒤에는 `npm install`을 하고, 그래도 안 되면 `.next` 폴더를 지운다.
- **커밋했는데 파일이 계속 "M"으로 보임**: 줄끝 문자(LF/CRLF) 차이라 내용은 같다.
- **스키마를 바꿨는데 `Unknown argument`**: 개발 서버가 예전 Prisma 도구를 들고 있었다. 서버를 껐다 켜면 된다.
- **머지 뒤 `package-lock.json`이 깨짐**: PR #28 머지 때 충돌 정리가 덜 됐다. 다른 팀원이 수습해서 develop에 다시 올릴 예정이다.
